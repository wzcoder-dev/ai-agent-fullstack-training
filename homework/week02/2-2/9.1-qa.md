# 9.1 口头验收记录

> **总分：6.8 / 10**（链路 8 + 四组区别 4 / 7 / 8 / 6，取平均）
> 规律：流程骨架全对，术语标签与归属关系是主要失分区。

## 第 1 问：画执行链路（8 / 10）

**我的回答：**

> 注册（模型的定义加载到 agent 中）→ 发现（模型在本轮中可以使用的工具）→ 快照（冻结 tool 的版本，发给模型和 runtime 检查时是一个版本）→ Tool Call（模型返回的工具调用信息，包含 tool_call_id、name、参数）→ prepare（校验+鉴权+查验）→ execute（执行工具）→ finalize（对结果进行查验，要符合输出格式，有错误的话也要符合 error schema）→ Tool Result（能够输出到 agent loop 的结构结果）

**点评：**

- ✅ 八环节顺序全对；快照"同版本"一句最好；finalize 对应 Output/Error Schema 位置正确。
- ⚠️ 注册归属说反：注册的是**工程师定义的工具契约**（ToolDefinition，name@version 组合键），模型不参与注册。
- ⚠️ Tool Result 漏了灵魂：必须**带回原始 tool_call_id** 写回消息历史。
- 补强：prepare 的完整内容是"从快照查找 → Input Schema 校验 → 权限/审批/风险拦截"，拒绝全部发生在 handler 之前。

**参考链路：**

> 注册（工程师把 ToolDefinition 登记进 Registry：name@version、重复检查）
> → 发现（按任务/权限决定本轮开放哪些工具——治理决策）
> → 快照（把本轮 Schema 与执行实现一起冻结，模型与 Runtime 用同一版本）
> → Tool Call（模型输出：tool_call_id + name + arguments JSON 文本）
> → prepare（从快照查找 → Input Schema 校验 → 权限/审批/风险拦截，拒绝不进 handler）
> → execute（受控执行：超时预算、非幂等写不自动重试、异常不外泄）
> → finalize（Output Schema 验收 / 错误归一化，包装结果）
> → Tool Result（带原始 tool_call_id 写回消息历史，交下一轮模型决策）

## 第 2 问-组 1：Tool Schema 与 ToolDefinition（4 / 10）

**我的回答：**

> tool schema 是包含 name version handler 等全部的参数，给 agent 来用的；tool definition 是给模型看的，只包含 name + description + 参数；因为内部信息不能交给模型来生成，只能是程序来控制。

**点评：** ❌ **两个术语接反**（推理方向正确）。

- **Tool Schema**：发给**模型**的公开协议——name + description + parameters（JSON）。
- **ToolDefinition**：**服务端**完整契约——Input/Output/Error Schema、permission、risk、timeout、idempotent、**handler**。
- 关系：Definition 是源，Schema 是它的**安全投影**（`to_model_tool()`）——单一事实来源。
- 记法：Schema 薄、出门给模型；Definition 全、留在家。

## 第 2 问-组 2：Registry 与 Runtime（7 / 10）

**我的回答：**

> registry 是管理 agent 有多少工具的，runtime 是管理检验+鉴权+拦截，来确定工具能不能去执行的。

**点评：**

- Registry：不只"多少"，是"**哪些 + 什么版本**"（清单与版本库存）。
- Runtime 只答了上半场：**prepare + execute + finalize 全场裁判**——还包括受控执行与结果包装。
- 分开的理由：一个管库存生命周期，一个管单次调用纪律；快照隔离让 Registry 中途变更不影响执行中的调用（9.2 验收第 4 条）。

## 第 2 问-组 3：工具发现 与 模型选工具（8 / 10）

**我的回答：**

> 工具发现是在模型请求之前能看到哪些工具，并且用来冻结当前的工具版本；模型选工具是根据语义判断调用哪个工具，根据 tool schema 生成 tool call，并生成 tool_call_id。

**点评：**

- ✅ 发现的时机（请求前）与模型选工具的三要素都对。
- ⚠️ "冻结"是快照的活：发现只**产出**本轮开放清单，Snapshot 拿清单去冻结。
- 关系定性：**发现是出题人，模型是答题人**——选择范围由程序决定，选择本身由模型完成。

## 第 2 问-组 4：handler、Harness 与 Agent Loop（6 / 10）

**我的回答：**

> handler 只是工具按照参数去执行；harness 是 LLM 的外壳，约束 LLM 行为；agent loop 是整体流程的循环，是 harness 的一部分；准确来说 harness 包括 agent loop 和 handler。

**点评：**

- ✅ handler 定位、Loop ⊂ Harness 均对。
- ⚠️ Harness 太虚：它是工程外壳——装配模型客户端与 Runtime、注入可信上下文、治理策略、Trace。
- ❌ **handler 不在 Harness 里**。层次：Harness（编排）→ Tool Runtime（裁决）→ handler（业务）；Harness 直调 handler = 绕过 Runtime（4.3 问题③）。handler 与 Harness 之间永远隔着 Runtime。
